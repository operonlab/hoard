# Hoard UI 規格（P2-D）

狀態：提案，結論待 owner 確認。`[S#]` 指向 `research-notes.md` 的來源；標「未驗證」的是只靠記憶、沒有查到來源的說法，實作前要核對。

目標平台：macOS 27（Golden Gate）。材質系統仍叫 **Liquid Glass**，2026 年沒有改名，只是提高了可讀性、加了使用者可調的「透明 ↔ 著色」滑桿、工具列統一、側邊欄延伸到視窗邊緣 [S1][S2][S3][S4]。

## 0. 設計原則與平台基線

### 0.1 這個 app 要替人回答的三個問題

1. **什麼佔掉了空間？**（空間地圖、最大的檔案、檔案類型）
2. **哪些可以清？**（很久沒動的檔案、檢閱器裡的說明、丟到垃圾桶）
3. **最近多了什麼？**（最近變動）

每個畫面都先用一句人話回答它負責的問題，再給細節。WWDC26「Principles of great design」說簡單不等於極簡，有時是補上脈絡 [S24]；現在的 v0.1 只給數字不給結論，這是它像開發者工具的主因 [S68]。

### 0.2 平台基線（決定）

| 決定 | 內容 | 依據 |
|---|---|---|
| 只用系統元件拿 Liquid Glass | 視窗、工具列、側邊欄、檢閱器、sheet 全用 SwiftUI 標準元件，用最新 SDK 建置即自動套用新外觀。不自己畫玻璃。 | [S21][S2] |
| 內容層不放玻璃 | 空間地圖、表格是內容層，不加 `glassEffect`。 | [S2]「Don't use Liquid Glass in the content layer」 |
| 工具列、側邊欄不加自訂背景 | 移除現在自繪的按鈕列與背景色。 | [S21][S7] |
| 部署目標維持 macOS 14 | 本規格用到、有查到可用版本的 API 都在 macOS 14 以內（沒查到的列在 §13，都是長期存在的 API）；macOS 26 以上才有的 Liquid Glass 專用 API（`glassEffect`、`backgroundExtensionEffect`、`ToolbarSpacer`、`scrollEdgeEffectStyle`）一個都不需要。`Package.swift` 不必改。 | [S28][S29][S30][S37]，`Package.swift` 現為 `.macOS(.v14)` [S68] |
| 建置用含 macOS 27 SDK 的 Xcode | 沒有新 SDK 就拿不到新外觀。本機 Xcode 版本未驗證。 | [S21] |
| 尊重使用者的 Liquid Glass 滑桿、降低透明度、增加對比 | 系統元件自動處理；我們自訂的只有空間地圖，它不透明，不受影響。 | [S2][S3][S21] |
| 顏色只用系統語意色 | 不寫死 RGB；每個自訂色都要有淺色、深色、增加對比三種結果。 | [S15] |

### 0.3 從其他磁碟工具學到什麼

| 工具 | 留下 | 不學 | 依據 |
|---|---|---|---|
| WizTree | 目錄樹＋矩形樹圖並列；最大檔案預設前 1000 筆 | 背景有變動不更新（我們有 FSEvents） | [S58][S59] |
| DaisyDisk | 首頁先列磁碟與用量條；刪除前先集中檢查 | **永久刪除、不能復原**。我們一律丟到垃圾桶並可還原 | [S54][S56] |
| GrandPerspective | 滑過時在視窗底部顯示名稱與大小（固定位置，不會遮住圖） | 以資料夾上色（顏色沒有語意） | [S61] |
| CleanMyMac Space Lens | 先選位置再掃描；移除前先列清單檢查 | 泡泡圖（面積難比較） | [S62][S63] |
| macOS 儲存空間設定 | 用語平實；「在 Finder 中顯示」；依「上次取用」排序 | 只到類別層級，看不到哪個資料夾大 | [S50][S51] |

共同的弱點，也是我們現在就有的：顏色沒有意義（v0.1 是副檔名 hash 上色 [S68]）、術語（「矩形樹圖」「副檔名統計」）、不告訴人「這東西能不能刪」。

## 1. 視窗結構

### 1.1 骨架

`NavigationSplitView`（側邊欄＋內容）加上 `.inspector`（後緣檢閱器）。Apple 建議用分割視圖做「側邊欄＋檢閱器」版面 [S21]；`NavigationSplitView` macOS 13+ [S5]，`inspector(isPresented:content:)` macOS 14+ [S27]。取代現在的 `HSplitView`／`VSplitView` [S68]。

- 預設視窗 1280×800 pt；最小 960×620 pt（沿用）。
- 側邊欄寬 200 pt（可拖 180–260）。內容區最小 480 pt。檢閱器寬 280 pt（可拖 240–360）。窗格最小寬度要讓分隔線不會消失 [S12]。
- 視窗寬度不夠放三欄時先收檢閱器，再收側邊欄；兩者都能用工具列按鈕、「顯示方式」選單與快捷鍵叫回來 [S6][S12]。
- 側邊欄預設顯示，不預設隱藏 [S6]。

### 1.2 範圍（scope）模型

- 全 app 只有一個「目前範圍」：一個資料夾。側邊欄選的位置是掃描根；在空間地圖或清單裡打開資料夾，範圍就往下一層。
- 所有檢視（空間地圖、最大的檔案、檔案類型、很久沒動、最近變動、搜尋）都只看目前範圍。切換檢視不改範圍。
- 視窗標題＝目前範圍的資料夾名稱（不是 app 名稱，15 字元內，超過中段省略）[S7]；副標題＝狀態（見 §7.3）[S45]。
- 範圍的導覽歷史支援返回／前進（工具列 `‹ ›`、⌘[、⌘]）與上一層（⌘↑，同 Finder）。

### 1.3 側邊欄

`List` 套 `.sidebar` 樣式 [S6]。兩個區段，每區一層，不超過兩層 [S6]。

**位置**

| 列 | 圖示 | 名稱 | 尾端 | 行為 |
|---|---|---|---|---|
| 整個磁碟 | `internaldrive` | 卷宗名稱（例「Macintosh HD」） | 上次掃描結果，例「412 GB」；沒掃過不顯示 | 掃描 `/System/Volumes/Data`（沿用現行路徑 [S68]） |
| 家目錄 | `house` | 使用者帳號名稱（例「alex」），VoiceOver 唸「家目錄，alex」 | 同上 | 掃描 `~` |
| 最近（小標「最近」） | `folder` | 資料夾名稱；滑過顯示完整路徑 | 同上 | 最多 5 筆，最新在上；右鍵「從最近項目移除」 |
| 選擇資料夾… | `plus` | 「選擇資料夾…」 | — | 打開 `NSOpenPanel`（沿用 [S68]），⌘O |

把資料夾從 Finder 拖到側邊欄或內容區＝掃描它。

**檢視**

| 列 | 圖示（未驗證，見 §13） | 名稱 | 快捷鍵 | 尾端 |
|---|---|---|---|---|
| 空間地圖 | `square.grid.2x2` | 空間地圖 | ⌘1 | — |
| 最大的檔案 | `arrow.down.doc` | 最大的檔案 | ⌘2 | — |
| 檔案類型 | `chart.pie` | 檔案類型 | ⌘3 | — |
| 很久沒動的檔案 | `moon.zzz` | 很久沒動的檔案 | ⌘4 | — |
| 最近變動 | `arrow.up.arrow.down` | 最近變動 | ⌘5 | 淨變化超過 100 MB 時顯示，例「+2.1 GB」 |

- 名稱為使用者而取，不用技術詞：「矩形樹圖」改「空間地圖」，「副檔名統計」改「檔案類型」[S26]。
- 圖示顏色跟隨系統強調色，不用固定色 [S6]。
- 側邊欄底部不放任何重要資訊或動作 [S6]。FDA 狀態放在內容區橫幅（§2.3）。
- 圖示大小與列高跟隨「系統設定 › 外觀 › 側邊欄圖示大小」，`List(.sidebar)` 自動處理 [S6]。

### 1.4 工具列

統一工具列，三個區、最多三組 [S7]。

| 區 | 項目 | 說明 |
|---|---|---|
| 前緣 | 側邊欄開關（系統提供）、返回 `chevron.left`／前進 `chevron.right`、標題＋副標題 | 前緣項目不可自訂 [S7] |
| 中央 | 只在「空間地圖」檢視出現：分段控制「圖｜清單」 | 視窗窄時系統自動收進溢出選單，不自己做溢出選單 [S7]；`ToolbarOverflowMenu` 不支援 macOS [S31] |
| 後緣 | 重新掃描 `arrow.clockwise`（掃描中變成停止 `stop.fill`＋小轉圈）、搜尋欄位、檢閱器開關 `sidebar.trailing` | 後緣項目任何寬度都可見；搜尋放後緣 [S7][S9] |

- 只用符號、不加邊框；滑過顯示說明（`.help`）[S7]。
- 每個工具列項目都要在選單列有對應命令 [S7]（§9.4 快捷鍵表）。
- 不放「丟到垃圾桶」：它屬於選取項目，放在檢閱器、右鍵選單、選取列。

### 2.2 選擇「整個磁碟」或「家目錄」時：完整磁碟取用權限

事實：

- macOS 沒有 API 讓 app 要求或偵測完整磁碟取用權限（FDA），也不能把自己加進清單；只能請使用者自己去系統設定打開 [S46][S47]。
- Apple DTS 建議「直接做，再處理錯誤」[S46]。我們的掃描器本來就把讀不到的資料夾標成 `partial`／`unavailable` [S65]——**掃描結果本身就是權威訊號**。
- 社群常用試讀受保護檔案（例 `/Library/Preferences/com.apple.TimeMachine.plist`）來猜有沒有權限 [S46]；這不是 API，只拿來決定要不要先顯示說明，不拿來阻擋掃描。
- 開設定頁的 URL `x-apple.systempreferences:com.apple.preference.security?Privacy_AllFiles` 來自社群，現行程式已在用 [S46][S68]；macOS 27 上是否仍開到正確頁面未驗證。

流程：

1. 使用者點「整個磁碟」或「家目錄」。
2. 試讀探針。讀得到 → 直接掃描。讀不到、且使用者沒選過「先不用」→ 顯示 §2.2.1 說明 sheet。
3. 不論有沒有授權都能掃。沒權限的資料夾照三態規則顯示（§7.1）。
4. 掃描結束若有因權限讀不到的資料夾 → 顯示 §2.3 橫幅。
5. 使用者從系統設定回到 Hoard（app 重新變成作用中）→ 再試讀探針：
   - 讀得到 → 橫幅改成「已取得權限，重新掃描以補上先前讀不到的資料夾。［重新掃描］」
   - 仍讀不到 → 橫幅保留，多一行「如果你已經打開開關，請結束 Hoard 再重新打開。」（需要重開才生效是未驗證的經驗說法，所以用「如果」）

#### 2.2.1 說明 sheet

```

- `sheet(item:)` [S13]。預設鍵＝「打開系統設定」（後緣）。Esc＝「先不用，直接掃描」。
- 不用「允許」等字眼、不放系統畫面截圖 [S17]。
- 「打開系統設定」：開上述 URL；開不了時改打開「系統設定」並在 sheet 內顯示手動路徑「系統設定 › 隱私權與安全性 › 完整磁碟取用權限」[S49]。
- 「先不用」被選過一次後，以後點「整個磁碟」不再跳 sheet；之後只靠 §2.3 橫幅提醒。
- 不在 app 啟動時跳這個 sheet [S17][S11]。

### 2.3 權限橫幅（掃描後）

內容區頂端、範圍路徑列上方的非強制橫幅，不用警示框（警示不該只為告知 [S11]）。

```
┌───────────────────────────────────────────────────────────────────────────────┐
│ 🔒 有 23 個資料夾因為權限讀不到，所以總量顯示為「至少 412.3 GB」。 [授權方式…] [×] │
└───────────────────────────────────────────────────────────────────────────────┘
```

- 背景用 `Color.orange` 12% 不透明度（現行做法 [S68]），文字主色。
- 「授權方式…」打開 §2.2.1 sheet（按鈕改為「關閉」「打開系統設定」）。
- 「×」關掉後同一個掃描根不再顯示，直到下一次掃描又發現讀不到的資料夾。

### 2.4 掃描進度

第一次掃描（還沒有任何結果可顯示）時佔滿內容區：

```
┌──────────────────────────────────────────────────────────────────────────┐
│                                                                          │
│                      正在掃描「Macintosh HD」                              │
│                                                                          │
│          ▇▇▇▇▇▇▇▇▇▇▇▇▇▇▇▇▇▇░░░░░░░░░░░░░░░░░░░░░░  約 46%               │
│               以這顆磁碟已使用的 680 GB 估算                                │
│                                                                          │
│          已找到 312.4 GB・1,284,551 個檔案・83,207 個資料夾                  │
│          已經過 12 秒                                                     │
│                                                                          │
│                              [停止掃描]                                   │
│                                                                          │
└──────────────────────────────────────────────────────────────────────────┘
```

- 一律用線性進度條，不在轉圈與進度條之間切換 [S10]。
- **能估就給百分比**（確定型優先 [S10]）：
  - 整個磁碟：分母＝卷宗已使用容量。
  - 有上次結果的資料夾：分母＝上次的 `totalAlloc`。
  - 都沒有：不確定型進度條，只顯示計數。
  - 百分比最多停在 99%，掃完直接進結果；估計不準時寧可顯示不確定型，也不顯示會倒退或卡在 99% 很久的數字 [S10]。分母選卷宗已使用容量是否夠準（APFS 容器內其他卷宗、snapshot、可清除空間都會讓它偏大）未量測，見 §12 D6。
- 計數每秒更新最多 4 次；數字用千分位。資料來源 `ScanProgress` 的 `bytes`／`files`／`dirs`／`elapsed` [S66]。
- 說明文字要具體，不寫「載入中」[S10]。
- 「停止掃描」（⌘.）：直接停、回到前一個畫面（空白狀態或上一個結果），不跳確認——停下來只損失時間，沒有其他副作用 [S10]。
- **重新掃描**（已有結果）：舊結果留在畫面上可操作，工具列重新掃描鈕變成停止＋小轉圈（背景作業用不加標籤的小轉圈 [S10]），副標題顯示「正在重新掃描⋯ 312 GB」。掃完原地換成新結果，保留目前範圍與選取（現行 `rescan()` 已保留選取 [S68]）。
- 「目前正在掃哪個資料夾」「目前最大的資料夾」會讓等待更有感，但 `ScanProgress` 沒有這些欄位 [S66]；列為選配（§12 D3），本規格不依賴它。

- 對照表放在 app target 的一個檔案（例 `FileCategory.swift`），附單元測試；其他畫面（圖例、檔案類型、檢閱器）都引用同一份。
- `.app`、`.photoslibrary` 等套件其實是資料夾，照資料夾畫；檢閱器的「種類」寫出「App」「照片圖庫」。

**填色與標籤色規則**（這段是要寫成測試的契約）：

1. 格子填色＝類別系統色以 55% 不透明度疊在 `windowBackgroundColor` 上，**先算成不透明色再填**。增加對比開啟時改 75%。
2. 標籤色從「主要文字黑」與「主要文字白」中挑對比較高的那個，依實際算出的填色決定，不寫死白字（現行固定白字只在深色模式可讀 [S68]）。
3. 每一組（10 類別 ×〔淺色、深色〕×〔一般、增加對比〕×〔檔案填色、資料夾填色〕）的標籤對比都要 ≥ 4.5:1（標籤字小於 18 pt [S16]）。寫成單元測試，不靠目測。2026-10-20 實測 80 組全過，最低：檔案 4.60、資料夾 4.75。
4. 手算幾個例子（未用工具量測）：淺色模式藍色格配黑字約 9.9:1；深色模式黃色格配白字只有約 3.7:1、配黑字約 5.6:1。所以第 2 條必須依顏色動態決定。
5. 資料夾框（第一層資料夾）：填 `Color.primary` 6%、標題列 `Color.primary` 10%，標題文字主色、大小文字次要色。不套第 8 條。
6. 增加對比開啟時，每格加 1 pt 邊框（主色 40%）[S15][S16]。
7. **不只靠顏色**：類別也寫在圖例、資訊列、檢閱器；「區分時不只使用顏色」開啟時（`accessibilityDifferentiateWithoutColor` [S44]），寬高至少 40×28 pt 的格子在左上角畫類別符號 [S16]。
8. **資料夾依內容上色**：內層資料夾格（不是第一層資料夾框、也不是「其他 N 項」格）填它的**主要類別**——子樹裡計入位元組（硬連結與 APFS 複製只算一次）最多的類別——以 35% 不透明度疊在 `windowBackgroundColor` 上，先算成不透明色；增加對比開啟時改 55%。檔案維持第 1 條的 55%／75%，所以檔案永遠比資料夾濃。標籤色照第 2 條依實際填色挑。
   - 主要類別不到該資料夾位元組的 40% 時維持中性色：混合的資料夾不假裝成單一類別。
   - 資訊列：「資料夾・1,284 個檔案・主要是模型與資料（62%）」；中性的寫「資料夾・1,284 個檔案・類型混合」。
   - 圖例標示某類別時，主要類別是它的資料夾格保持亮，其餘變淡，與檔案格相同。
   - 計算在背景：對目前範圍的子樹走一遍，把每個檔案的計入位元組加進它所屬可見資料夾格的 10 個類別桶；依（範圍、樹的版本）快取。結果到之前先畫中性色，不擋繪製；樹在自動更新時沿用上一版結果，算好再換。~/workshop（約 85 萬個檔案）根層一遍約 0.15–0.2 秒。

## 5. 很久沒動的檔案

### 5.1 「沒動」怎麼定義（決定，待 owner 確認，§12 D1）

- **依「上次修改」判斷**。樹裡只有 `modTime`，沒有存取時間 [S65]。
- 不用存取時間（atime）：APFS 預設只在 atime 早於修改時間時才更新它，快速查看也不會更新，用它判斷「沒被看過」可能嚴重誤導 [S52]。要加也得改凍結中的 `ScanEntry`。
- macOS 儲存空間設定用的是「上次取用」[S51]；我們刻意不同，所以畫面上要寫明依據，不讓人以為是「上次打開」。
- 名稱「很久沒動的檔案」：口語、而且「動」涵蓋修改；不用「沒用過」，那是我們無法保證的說法 [S26]。
- 不用「垃圾」「浪費」這類評斷字眼 [S26]。

### 5.2 畫面

### 5.3 日期與大小的寫法

| 用途 | 寫法 | API |
|---|---|---|
| 表格裡的日期 | 相對日期、數字型，例「3 年前」「8 個月前」「昨天」以內用「今天」「昨天」 | `Date.RelativeFormatStyle`，`presentation: .numeric` [S42] |
| 滑過與檢閱器 | 相對＋完整日期，例「2 年前（2024年3月2日）」 | `Date.FormatStyle` 長日期 |
| 句子裡 | 用完整日期，不把相對日期字串嵌進句子（官方提醒會不合文法 [S42]） | — |
| 大小 | 十進位單位、和 Finder 一致，例「4.79 GB」「820.9 MB」 | `ByteCountFormatStyle(style: .file)` [S41]（現行 `ByteCountFormatter(.file)` 同義 [S68]） |
| 檔案數 | 千分位，例「893,238 個檔案」 | `formatted()` |

繁中輸出的實際字樣（例「3 年前」）是依 Foundation 在地化推測，未驗證；實作後以 zh-Hant 地區設定截圖核對。

## 6. 最近變動（上次掃描以來）

### 6.1 前提（工程前置，§12 D2）

現在只有聚合數（目錄數、新增／移除節點數、位元組差），而且 snapshot 每次存檔都覆寫，沒有保留可比較的基準 [S67]。本畫面需要：一份「比較基準」（上次完整掃描時每個節點的大小），以及逐節點的差值計算。

### 6.2 定義

- 比較基準＝這個位置上一次完整掃描完成時的結果。
- 差值＝目前 `totalAlloc` − 基準 `totalAlloc`；新出現的項目差值＝現在大小；消失的項目差值＝負的基準大小。
- 只列 |差值| ≥ 1 MB 的項目（門檻寫在畫面上）。
- 「從現在重新比較」把目前結果設成新基準。不跳確認：它不動任何檔案。

### 6.3 畫面

```

│ +12.4 GB            │ −3.1 GB             │ +9.3 GB             │
└────────────────────┴────────────────────┴────────────────────┘

┌─────────────────────────────────┬───────────┬──────────┬──────────┐
│ 名稱                             │ 變化 ▼    │ 現在      │ 之前      │
├─────────────────────────────────┼───────────┼──────────┼──────────┤
│ ▾ 📁 outputs                     │ +8.2 GB   │ 42.1 GB  │ 33.9 GB  │

- 以資料夾階層呈現、依 |差值| 遞減；展開看子項目。重用 `NSOutlineView` 或 `List`＋`DisclosureGroup`。
- **不只靠顏色**：變大用 `⬆`＋「+」，變小用 `⬇`＋「−」（U+2212）；「新增」「已移除」用文字標籤 [S16]。顏色只是輔助：變大用次要強調（橙），變小用綠；不用紅色。
- 已移除的列文字用次要色、不能選取執行檔案動作（只能拷貝路徑）。

- 沒有基準：`ContentUnavailableView`「還沒有可以比較的掃描」，說明「Hoard 會記住這次的結果。下次打開時，這裡會列出期間變大、變小、新增和移除的項目。」[S33]
- 沒有變化：「自 10月18日 以來沒有超過 1 MB 的變化。」

## 7. 部分／無法取得的大小、錯誤、載入中

### 7.1 三態大小的顯示規則（所有畫面一致）

`ScanStatus` 三態：`partial` 與 `unavailable` 絕不能看起來像精確值或 0 [S65]（AGENTS.md 契約）。

| 狀態 | 表格／清單 | 檢閱器 | 空間地圖 | 百分比 | VoiceOver |
|---|---|---|---|---|---|
| complete | 「4.79 GB」 | 「4.79 GB」 | 按大小畫 | 「37.8%」 | 「4.79 GB」 |
| partial | 「≥ 4.79 GB」＋次要色 `lock.fill`，滑過「有些內容沒有權限讀取，實際大小至少這麼多」 | 「至少 4.79 GB」＋說明行「部分內容沒有權限讀取」＋「授權方式…」連結 | 按已知大小畫＋斜紋（45°、間距 6 pt、1 pt、主色 25%），標籤加「≥」 | 「≥ 37.8%」 | 「至少 4.79 GB，部分內容無法讀取」 |
| unavailable | 「無法讀取」次要色＋`lock.fill` | 「無法讀取」＋說明「沒有權限讀取這個資料夾」＋「授權方式…」 | **不畫**（大小未知，無法給面積）；計入圖例列「🔒 23 個資料夾無法讀取」，點了以 popover 列出路徑 | 「—」，滑過「大小未知」 | 「大小未知，沒有權限讀取」 |

- 取代現行的「≥ X ⚠︎」與「—」[S68]：⚠︎ 在 macOS 慣例裡代表可能遺失資料 [S11]，這裡的意思其實是「沒權限」，所以改用鎖頭；「—」單獨出現會被讀成 0 或沒資料，改寫成文字。
- 排序：依已知大小排；`unavailable` 不論升降冪都排最後。
- 加總：任何子項是 partial／unavailable，上層就是 partial（現行掃描器已如此傳遞 [S65]），標題副標題寫「至少 412.3 GB」。

### 7.2 載入中

## 8. 丟到垃圾桶與其他破壞性操作

### 8.1 原則

- **只提供「丟到垃圾桶」**（`FileManager.trashItem`，現行已用 [S68]），不提供永久刪除，也不提供清空垃圾桶。這是和 DaisyDisk 最大的差別：它永久刪除、不能復原 [S54]。
- 依 owner 要求，丟之前一律確認，而且確認畫面要說清楚會發生什麼。
- HIG 說可復原的動作不必跳警示 [S11]；我們仍確認（owner 要求），但讓確認鈕成為預設鍵、並提供還原，把摩擦降到最低。
- 使用者是刻意選擇丟垃圾桶，確認鈕不套 destructive 樣式 [S11]。

### 8.2 確認 sheet

```
┌───────────────────────────────────────────────────────────────────┐
│  要把 3 個項目丟到垃圾桶嗎？                                        │
│                                                                   │
│  🎬 render_final_v3.mov      6.2 GB    ~/Movies/2023 專案          │
│  📦 Xcode_15.4.xip           4.1 GB    ~/Downloads                 │
│  📁 DerivedData             12.8 GB    ~/Library/Developer/Xcode   │
│                                                                   │
│  共 23.1 GB                                                       │
│                                                                   │
│  • 這些項目會移到垃圾桶。之後可以從垃圾桶放回原處，                 │
│    或在 Hoard 選「編輯 › 還原」。                               │
│  • 清空垃圾桶後，才會真正釋放約 23.1 GB。                           │
│  • 其中 1 個檔案和其他檔案共用磁碟空間（APFS 複製或硬連結），        │
│    實際釋放的空間可能比較少。                                       │
│  ⚠︎ 其中有 App 的資料（位於 ~/Library）。刪除後，相關 App 可能需要  │
│    重新下載資料，或無法正常運作。                                   │
│                                                                   │
│                                        [取消]  [丟到垃圾桶]        │
└───────────────────────────────────────────────────────────────────┘
```

- `sheet(item:)` [S13]（現行已是 sheet [S68]）。
- 標題：一個項目「要把「model.safetensors」丟到垃圾桶嗎？」；多個「要把 3 個項目丟到垃圾桶嗎？」。
- 清單最多列 5 筆，其餘「還有 7 個項目」。
- 條件行：
  - 「共用磁碟空間」只在選取中有 `linkCount > 1` 或 `cloneID ≠ 0` 的檔案時出現 [S65]。
  - ⚠︎ 行只在選取中有 `~/Library` 內或 `.app` 內的項目時出現。這是「可能意外遺失資料」的情境，可以用 `exclamationmark.triangle` [S11]；一般丟垃圾桶不用它 [S11]。
- 按鈕：「取消」（前緣，Esc／⌘.）、「丟到垃圾桶」（後緣、預設鍵）[S11]。不提供「不再詢問」（owner 要求確認）。
- 「約 23.1 GB」用去重後的 `totalAlloc` 加總。

### 8.3 不允許丟的項目

選單與按鈕直接停用，`.help` 說明原因（不讓人按了才被拒）：

- 掃描根本身、家目錄、`/Applications` 本身
- `/System` 以下、`/Library`、`/usr`、`/bin`、`/sbin`、`/private`
- 「其他 N 項」合併格、`unavailable` 項目、已移除的項目

說明文字：「「Library」是系統需要的資料夾，Hoard 不會把它丟到垃圾桶。」DaisyDisk 也拒收 `/System`、`/Library`、家目錄 [S54]。

### 8.4 丟完之後

- 樹立即移除該子樹、大小往上更新（現行 `removeSubtree` [S68]）。
- 內容區底部出現非強制橫幅「已丟到垃圾桶：3 個項目，23.1 GB。［還原］［打開垃圾桶］」，10 秒後收起；同時發 VoiceOver 公告同一句 [S25]。
- 「編輯 › 還原丟到垃圾桶」（⌘Z）：用 `trashItem` 回傳的 `resultingItemURL` 把項目搬回原處、樹重新插入。同一個 session 內有效。現行程式傳 `resultingItemURL: nil` [S68]，要改。

## 9. 外觀與無障礙

### 9.1 淺色／深色、增加對比、Liquid Glass 設定

- 全部用系統語意色與 §3.2 的規則；淺色、深色、增加對比都要過 §3.2 第 3 條的對比測試 [S15][S16]。
- 系統元件自動因應 Liquid Glass 滑桿、降低透明度、增加對比 [S21]。空間地圖不透明，不受影響。

### 9.2 文字大小（macOS 的 Dynamic Type 替代）

macOS 不支援 Dynamic Type [S14]，所以：

1. 所有文字用系統文字樣式（Body 13 pt 為預設，最小 10 pt）[S14]。
2. 側邊欄跟隨系統的側邊欄圖示大小 [S6]。
3. App 自己的文字大小設定：「顯示方式 › 放大文字（⌘+）／縮小文字（⌘−）／實際大小（⌘0）」，85%、100%、115%、130%、150%、175%、200% 七段，存在 `AppStorage`。套用到空間地圖標籤、表格字級與列高、檢閱器。HIG 建議文字能放大到 200% [S16]。SwiftUI 的 `dynamicTypeSize` 在 macOS 上是否影響字級未驗證，所以自己乘比例，不依賴它。

### 9.3 VoiceOver

- 空間地圖（`Canvas`）用 `accessibilityChildren` 提供逐格元素，正是官方替 Canvas 圖表示範的做法 [S34]：
  - 容器標籤「空間地圖，workshop，111.5 GB，顯示 42 個項目」。
  - 每格：標籤「outputs，資料夾」，值「42.1 GB，佔 workshop 37.8%」；檔案加類別「影片」。
  - 只提供目前範圍內依大小前 100 格，順序＝大小遞減（不是畫面位置）。
  - 自訂動作「打開」「在 Finder 中顯示」「快速查看」「丟到垃圾桶」[S25]。
  - 選配：轉子「最大的項目」[S35]。
- 三態大小的唸法見 §7.1。
- 圖示按鈕都有文字標籤（工具列 `.help` 與 `accessibilityLabel` 同字）。
- 掃描完成、丟到垃圾桶、還原、自動更新大幅變化（> 1 GB）時發公告 [S25]；自動更新的小變化不公告。

### 9.4 鍵盤

全部功能都能只用鍵盤完成 [S16]。Tab 在側邊欄、內容、檢閱器之間移動焦點。

| 快捷鍵 | 命令 | 選單 |
|---|---|---|
| ⌘O | 選擇資料夾… | 檔案（沿用 [S68]） |
| ⌘R | 重新掃描 | 檔案（沿用） |
| ⌘. | 停止掃描 | 檔案 |

## 12. 工程前置需求與待決

以下需要 owner（或對應 slice 的負責人）決定。每題附推薦。

**D1. 「很久沒動」用哪個日期**
- A（推薦）：v1 用「上次修改」（資料已存在 [S65]），畫面寫明依據。
- B：在 A 之上，只替畫面上看得到的列、以 Spotlight 的「上次打開」補一欄（app 端延遲查詢，不改凍結契約）。Finder「上次打開」的資料來源有爭議 [S52]，要先驗。
- C（不推薦）：掃描時讀 atime。要改凍結中的 `ScanEntry`，而且 APFS 預設下 atime 不可靠 [S52]。

**D2. 「最近變動」需要比較基準**
- 現在 snapshot 每次覆寫、沒有逐項差異 [S67]。需要在 S-INC slice 新增 API（新檔，例 `IncrementalBaseline.swift`）：每次完整掃描完成時另存一份基準（或每個節點的路徑→大小表），以及計算差異樹的函式。推薦：另存基準 snapshot 檔，與滾動快取分開。

**D3. 掃描進度的額外欄位（選配）**
- 「目前在掃哪裡」「目前最大的資料夾」需要擴充 `ScanProgress`，它的公開簽名在凍結名單內，屬 main line 決定。本規格不依賴它；推薦先不做。

**D4. 已知資料夾的白話說明（選配，P2）**
- 檢閱器加一行「這是 Xcode 的建置快取，可以重建」之類的說明，對一般人最有幫助，但每一條都要查證，寫錯會誤導人刪東西。推薦延後，另開題。

**D5. 檔案類別**
- 「模型與資料」「設計與 3D」是照 owner 磁碟加的（§3.2）。推薦保留。

**D6. 整個磁碟掃描的百分比分母**
- 卷宗已使用容量包含其他卷宗、snapshot、可清除空間，可能讓百分比偏低。需要實測；誤差大就退回不確定型進度條（§2.4）。

**D7. 簽章與 FDA**
- `make-app.sh` 是 ad-hoc 簽章（`README.md`）。TCC 授權綁定程式簽章，ad-hoc 簽章每次重建都會變，可能每次重建都要重新授權——這是經驗說法，未驗證。若屬實，建議 S3 slice 改用固定的開發者憑證簽章。

**D8. 部署目標**
- 推薦維持 macOS 14（§0.2），不改 `Package.swift`。若 owner 想用 macOS 26+ 專屬的玻璃 API，才需要 main line 調整。
